ℹ️ About the Case Study

Credit card fraud detection is a binary classification problem: each transaction is classified as legitimate or fraudulent. The main challenge is class imbalance. A model can appear highly accurate simply by predicting the majority class, while still missing fraudulent transactions.

The project covers the end-to-end machine learning lifecycle:

  • Data Cleaning & Preparation:Remove duplicate records, prepare the features, and scale numerical data using training data to avoid data leakage.
  • Class Imbalance:Compare approaches including random oversampling, SMOTE, ADASYN, undersampling, Edited Nearest Neighbours, and class weighting.
  • Model Comparison:Evaluate classification models using precision, recall, and F1-score rather than relying on accuracy alone.
  • Hyperparameter Tuning:Use Optuna to tune the XGBoost model.
  • Decision Threshold Selection:Use the validation precision-recall curve to select a threshold that maximizes F1-score.
  • Final Evaluation:Evaluate the selected model on the held-out test set, which is kept separate from model selection and threshold tuning.

📊 Key Findings

XGBoost produced the strongest overall validation results among the evaluated approaches. Threshold selection improved the validation precision-recall balance, but the final test results showed lower recall than validation.

On the test set, precision was 98.6% and recall was 72.6%, with an F1-score of 0.836. This means that most transactions flagged as fraud were genuinely fraudulent, while the model still missed some actual fraud cases.

The results demonstrate why fraud detection requires careful evaluation of both false alarms and missed fraud, particularly when the target class is rare.
